# YaMusic

A Windows desktop client for Yandex Music, written in Python with wxPython —
built for keyboard-only use with NVDA screen-reader feedback.

## What it is

YaMusic wraps the `yandex_music` API in a native wx window with a menu bar,
no browser and no official client in the loop. Every action announces its
result through NVDA (`nvda.say`), and the interface is driven by menus,
list boxes and keyboard shortcuts rather than by mouse targets: playback
controls are keys, and the currently selected item is what the action
applies to. That makes it usable without a screen, which is the whole point
of the project.

What you can do in it:

- **Main** — Daily Playlist, Premiere (recent tracks), Deja vu (never heard),
  Missed likes, a playlist generated by Alice, and radio stations.
- **Collection** — liked tracks, liked albums, liked artists, liked playlists,
  with like/unlike from the keyboard.
- **Offline player** — play local files and pick the output device.
- **Search** — by track/album/artist, plus search for another user's public
  playlists by pasting a Yandex Music link (`url_manager` parses it and copies
  ids back to the clipboard).

Authentication is by OAuth token. If no token is stored, the login dialog can
also exchange a username and password for one via `https://oauth.yandex.ru/token`.
The token, the user name and the password are kept in
`%LOCALAPPDATA%\Ya_music\config.json`.

## Requirements

- **Windows.** The app is Windows-only as it stands: `nvda.py` loads
  `nvdaControllerClient64.dll` through `ctypes.windll`, and `settings.py`
  reads `%LOCALAPPDATA%` at import time. On other platforms it will not start
  without changes to those two.
- **Python 3** with `pip`.
- **libmpv** — playback goes through the bundled `mpv.py` (a copy of
  [python-mpv](https://github.com/jaseg/python-mpv)) which loads `mpv-1.dll`
  from the working directory. See "libmpv" below.
- **NVDA**, if you want the speech feedback. Without NVDA running, the
  `nvda.say` calls simply do nothing.

## Building from source

There is no build step and no packaging in the repository — the program is run
as a script. To get it going from a clean machine:

1. Install Python 3 and make sure `python` and `pip` are on `PATH`.

2. Get the sources:

   ```
   git clone https://github.com/Nasferus/ya-music.git
   cd ya-music
   ```

3. Install the Python dependencies:

   ```
   pip install yandex_music wxPython pyperclip requests
   ```

   Or, from the same file that lists them for `pip`:

   ```
   pip install -r requirements.txt
   ```

   Those four are the real dependencies. `albums.py`, `artists.py`,
   `player.py`, `radio.py`, `station.py` and friends are part of the
   repository itself, not packages.

4. **libmpv.** Download a Windows build of mpv (the
   [mpv-player-windows](https://sourceforge.net/projects/mpv-player-windows/files/libmpv/)
   builds are the usual source), take `mpv-1.dll` out of it and put it next to
   the scripts — in the same directory you will run from. `mpv.py` looks for
   `mpv-1.dll` in the current working directory, so running from elsewhere
   without the DLL there fails with `Cannot find libmpv in the usual places`.

5. **NVDA controller client.** `nvda.py` loads `./nvdaControllerClient64.dll`
   relative to the working directory. That file comes with the
   [NVDA Controller Client](https://www.nvaccess.org/files/nvda/documentation/controllerClient.html)
   package (it is used by applications that drive NVDA directly). Put it next
   to the scripts as well.

6. Run it from that directory:

   ```
   python main.py
   ```

   The menu bar is at the top; the login dialog appears if no token is
   configured yet.

### A note on versions

The code was written against `yandex_music` 2.2.0. Later versions may need
adjustment — see "Known workarounds" for one place where the library's
behaviour is patched at runtime.

## Known workarounds

### `User.login` on personal playlists (`main.py`)

`yandex_music`'s `User` model declares `login` as a required field, but the API
does not return `login` inside `playlist.made_for.user_info`, and
`MadeFor.de_json` calls `User.de_json` on that payload unconditionally. The
result is a `TypeError: User.__init__() missing 1 required positional argument:
'login'` on every personal playlist — Daily, Premiere, Deja vu, Missed likes
and Alice.

The behaviour is upstream and long-standing (present since 2022-09-04, issue
[#338](https://github.com/MarshalX/yandex-music/issues/338) / PR
[#484](https://github.com/MarshalX/yandex-music/pull/484)), so all 2.x releases
are affected and downgrading does not help.

`main.py` wraps `User.de_json` at startup and defaults a missing `login` to an
empty string. **If upstream ever fixes `MadeFor.de_json`, remove the wrapper**
(see `_patch_yandex_music_user_login`).

### Playlist like keys

The API's like endpoints take the playlist identified as `owner_id:playlist_id`
— that is, `uid:kind`. The older code in this repository built the key the
other way round, which silently liked the wrong playlist.
